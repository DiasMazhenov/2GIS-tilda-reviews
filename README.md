# 2GIS Tilda Reviews

Универсальный адаптивный блок отзывов **2ГИС для Tilda T123**, написанный на HTML, CSS и JavaScript. Без сервера и сборки. Есть сквозной режим и фильтрация по упоминанию врача на отдельных страницах.

> Неофициальная интеграция. Публичный endpoint виджета 2ГИС, его ключ, CORS, пагинация и правила использования могут изменяться. Проверяйте право на отображение и выборочную фильтрацию отзывов на коммерческом сайте.

## Вариант: CSS в T123, HTML и JavaScript из CDN

**Используйте [tilda-css-only.html](./tilda-css-only.html).** Внутри T123 останутся только CSS (исходные стили Comfort Clinic), пустой контейнер с ID филиала и подключение одного скрипта:

```html
<!-- ID филиала задаётся один раз -->
<section class="clinic-reviews" data-clinic-reviews data-branch-id="70000001101966397"></section>
<style>/* ваши локальные стили .clinic-reviews и .cr-* */</style>
<script defer src="https://cdn.jsdelivr.net/gh/DiasMazhenov/2GIS-tilda-reviews@main/dist/embed.js"></script>
```

`dist/embed.js` создаёт стандартную HTML-разметку отзывов, затем инициализирует API-запросы, поиск врача и кнопку «Загрузить еще». Не нужно копировать в T123 ни HTML карточек, ни JS-функции. CSS управляется исключительно вами через T123. Указывать `YOUR_BRANCH_ID` надо лишь один раз. Скрипт работает и в сквозном T123.

**Внимание:** версия с локальными HTML + CSS и внешним `dist/reviews.js` (файл `tilda-cdn.html`) остаётся как альтернативный способ установки. Ссылка `@main` в jsDelivr обновляется с задержкой из-за кэширования CDN; это не мгновенная публикация изменений. Для исправлений JS в `embed.js` пока требуется синхронизация логики с `reviews.js`.

## Подключение через CDN (HTML и CSS локально)

Чтобы не заменять JavaScript в Tilda после каждого обновления, используйте [tilda-cdn.html](./tilda-cdn.html). Скопируйте содержимое файла целиком в T123, заменив `YOUR_BRANCH_ID` только в одном месте. В этом варианте HTML и исходные CSS-стили остаются в Tilda, а JavaScript загружается по адресу:

```html
<script defer src="https://cdn.jsdelivr.net/gh/DiasMazhenov/2GIS-tilda-reviews@main/dist/reviews.js"></script>
```

**Не подключайте** `tilda-block.html` через `<script src>`: этот файл содержит разметку и CSS, а не один JavaScript. Для CDN нужен `dist/reviews.js`.

Изменение `dist/reviews.js` в GitHub распространяется через jsDelivr не мгновенно, поскольку CDN кэширует файлы, в том числе по ссылке с `@main`. Для контролируемых выпусков лучше использовать теги версий. Изменения стилей в `tilda-cdn.html` не обновятся на Tilda автоматически: CSS остаётся локальным. Также важно синхронизировать `dist/reviews.js` с логикой из `tilda-block.html` при будущих правках.

## Установка за 3 шага

1. Откройте [tilda-block.html](./tilda-block.html), скопируйте **весь** файл и вставьте в блок **T123 → HTML** в Tilda. При необходимости сделайте блок сквозным стандартными средствами Tilda.
2. В открывающем теге `<section>` укажите значения **своей организации**. Достаточно указать ID филиала только один раз в `data-branch-id`. Скрипт сам формирует ссылку на отзывы:
   - `data-branch-id` — **единственное место для ID филиала**, например из адреса его карточки `https://2gis.kz/firm/70000001101966397/...`.
   - `data-api-key` — **необязательный** публичный ключ виджета для конкретного сайта. Если не указан, используется встроенный ключ по умолчанию. Это удобство не гарантирует, что 2ГИС примет запрос с другого домена.
   - `data-title` и `data-subtitle` — заголовки секции.
3. Опубликуйте страницу и убедитесь, что отзывы появились. Проверяйте на **опубликованном** сайте, а не только в редакторе Tilda.

Не требуется подключать дополнительные библиотеки. **Важно:** ключ не извлекается автоматически из ID филиала; код использует встроенный публичный ключ из исходного виджета. Если он перестанет работать, получите разрешённый ключ для своего сайта и укажите `data-api-key="ВАШ_КЛЮЧ"`. Не используйте секретные серверные API-ключи в HTML.

Пример минимальной настройки:

```html
<section class="clinic-reviews" data-gis-reviews
  data-branch-id="70000001101966397">
```

Это фрагмент открывающего тега, а не замена всего файла T123.

## Настройки

| Атрибут в `<section>` | По умолчанию | Описание |
|---|---|---|
| `data-branch-id` | `YOUR_BRANCH_ID` | Обязательный числовой ID филиала 2ГИС |
| `data-api-key` | встроенный ключ | Необязательное переопределение публичного ключа виджета |
| `data-display-limit` | `6` | Число видимых карточек, от 1 до 30 |
| `data-search-limit` | `200` | Максимум проверяемых отзывов на странице врача, от 1 до 500 |
| `data-positive-min` | `4` | Минимальная оценка резервных отзывов, от 1 до 5 |
| `data-title` | `ОТЗЫВЫ НАШИХ ПАЦИЕНТОВ` | Заголовок |
| `data-subtitle` | `Спасибо за ваше доверие` | Подпись |

Оформление восстановлено из исходного блока Comfort Clinic: `.clinic-reviews` и классы `cr-*`. Цвет акцентов меняется через `--cr-accent`; фон и прочие цвета заданы в исходном CSS. Добавлены только стили кнопки `.cr-load-more`. На десктопе сетка из трёх карточек, на планшете из двух, на телефонах горизонтальная прокрутка.

## Отзывы конкретного врача

На страницах конкретных врачей **достаточно указать класс `.doctor` у текстового элемента с ФИО** (в Zero Block: CSS Class Name). Отдельный T123-маркер необязателен, но также поддерживается: из [examples/doctor-marker.html](./examples/doctor-marker.html):

```html
<div data-gis-doctor-reviews hidden></div>
```

Блок ищет ФИО в текстовом элементе с классом `.doctor` на этой странице, например:

```html
<h1 class="doctor">Ахметова Айгуль Сериковна</h1>
```

Можно не добавлять класс `.doctor`, если ФИО явно задано в маркере:

```html
<div data-gis-doctor-reviews data-doctor-name="Ахметова Айгуль Сериковна" hidden></div>
```

Или указать другой класс, откуда брать имя:

```html
<div data-gis-doctor-reviews data-doctor-selector=".doctor-name" hidden></div>
```

На **обычных страницах**, где нет `.doctor` и маркера, показываются последние доступные текстовые отзывы (любой оценки). На **странице врача** скрипт просматривает до 200 последних отзывов и отображает отзывы с фамилией врача либо сочетанием имени и отчества (упоминание одного имени недостаточно). При отсутствии совпадений среди проверенных отзывов показывает общие отзывы клиники с оценкой **4–5 звёзд**.

Важно: поиск по имени может ошибочно находить тёзок. Алгоритм использует приближённые совпадения окончаний и не является морфологическим анализатором. Положительность резервных отзывов определяется **только оценкой**, не анализом текста. Общий рейтинг 2ГИС не является персональным рейтингом врача.

## Кнопка «Загрузить ещё 3»

Под сеткой отзывов находится кнопка **«Загрузить ещё 3»**. При открытии страницы показываются 6 отзывов (`data-display-limit="6"`), каждый клик добавляет до 3 карточек без перезагрузки страницы. Если больше подходящих отзывов нет, кнопка скрывается.

На обычных страницах новые отзывы запрашиваются у 2ГИС по мере необходимости. На страницах врачей поиск сначала проверяет до `data-search-limit` отзывов и дальше показывает из найденных совпадений по 3; если таких отзывов недостаточно, кнопка исчезает. При отсутствии упоминаний врача используется резервная выборка оценок от `data-positive-min`.

Ограничение: кнопка зависит от работы пагинации `offset` в публичном API 2ГИС; если API её не поддерживает, загрузка следующих отзывов будет недоступна. Настройка количества добавляемых отзывов пока фиксирована в коде: `step=3`.

## Поведение и ограничения

- Длинные тексты раскрываются кнопкой «Читать полностью».
- Обновление запускается каждые 5 минут, если страница видима и пользователь не взаимодействует с блоком.
- Загрузка ограничена 15 секундами на API-запрос.
- Для поиска врача используются `limit` и `offset`. Поддержка пагинации зависит от стороннего API; если сервис игнорирует offset или блокирует запросы, охват может быть меньше 200 отзывов.
- В случае ошибки API показывается сообщение и ссылка на карточку 2ГИС.
- Текст отзывов выводится через `textContent`, чтобы не выполнять HTML из стороннего ответа.

## Диагностика

Если отзывы не загружаются, откройте DevTools → Network и проверьте запрос к `public-api.reviews.2gis.com`:

- **401/403:** проверьте ключ и условия доступа.
- **CORS:** сервер не разрешил запрос с домена вашего сайта; клиентским кодом это не исправить.
- **Нет упоминаний врача:** проверьте маркер, текст `.doctor` или `data-doctor-name`, увеличьте `data-search-limit` при необходимости.
- **Пустой список:** API может не вернуть нужные текстовые отзывы в пределах доступной выборки.

### Правовая оговорка

Отображение отфильтрованной выборки отзывов может ограничиваться правилами 2ГИС. Перед публикацией убедитесь, что использование публичного API и выборочный показ допустимы для вашего проекта.

## Единый ID филиала

В начале `tilda-block.html` найдите комментарий `НАСТРОЙКА` и замените `YOUR_BRANCH_ID` только в `data-branch-id` открывающего тега секции. Ссылка «Все отзывы в 2ГИС» создаётся автоматически на основе этого ID. Публичный ключ по умолчанию остаётся встроенным; при необходимости его можно переопределить атрибутом `data-api-key`.

## Диагностика поиска по врачу

На опубликованной странице врача откройте DevTools → Console. При успешном распознавании будет сообщение `[2GIS Reviews] Включён поиск упоминаний врача: ...`. Если сообщения нет, проверьте, что элемент `.doctor` действительно есть в DOM к моменту загрузки и содержит ФИО. Для нестандартной страницы можно использовать явный маркер `data-gis-doctor-reviews data-doctor-name="Фамилия Имя Отчество"`. Скрипт не ищет имена непосредственно на сервере 2ГИС, он фильтрует загруженные тексты. При отсутствии совпадений в проверенной выборке показываются отзывы с оценкой от 4.

## Выделение имени врача

На страницах врача найденные в тексте отзыва упоминания имени или фамилии автоматически выделяются жирным (`<strong>`). Используется то же приближённое сопоставление, что и при фильтрации. Остальной текст отзыва остаётся обычным; в режиме общих отзывов подсветки нет. Текст вставляется безопасно через текстовые узлы, без обработки HTML из API.

### Защита от тёзок

Начиная с обновления алгоритма, простое совпадение по имени **не засчитывается**. Для полного ФИО подходит упоминание фамилии или сочетания имени и отчества рядом (расстояние до двух слов); для двухкомпонентного имени требуются оба компонента рядом. Это уменьшает вероятность показа отзывов о тёзках, но не гарантирует абсолютную идентификацию. Отзывы только с именем без других признаков больше не учитываются. Если совпадений нет, действует резерв с оценкой от `data-positive-min`.
